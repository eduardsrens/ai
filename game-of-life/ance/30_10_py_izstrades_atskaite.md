# Game of Life development report

## Goal

Extend the Conway "Game of Life" program so the user can create, color, save, and restore patterns, as well as draw with central symmetry.

## Development process

### 1. Resetting the starting pattern

Added a **Reset** button. The program saves the original pattern created by the user or generated by the randomization function. Reset stops the simulation, restores that pattern, and sets the generation count to zero. The existing **Clear** button still clears the board separately.

### 2. Saving and loading drawings

Added **Save** and **Open** buttons. Drawings can be saved under a name and loaded later. They are stored in the JSON file `game_of_life_drawings.json` next to the program file. Before overwriting an existing drawing, the program asks for confirmation.

The save format now includes validation. Older single-color drawings are also supported so previously saved patterns remain openable.

### 3. Drawing with mouse drag

The area can be painted by holding the left mouse button and dragging. Right-click erases a cell. When the first generation is drawn, the program restores a copy of the initial pattern from the reset state.

### 4. Choosing a color for each cell

The **Color** button opens a color picker. The new color is applied only to cells drawn after the selection; previously colored cells keep their color. The color is also included in the saved drawing.

A color-selection bug was fixed by using the RGB tuple returned by the Tkinter dialog instead of a hex string starting with `#`.

### 5. Mixing colors across generations

Cell state and color are stored separately. Surviving cells keep their own color, while new cells receive the average RGB value of neighboring live cells. This allows regions of different colors to evolve into blended tones according to the Game of Life rules.

### 6. Central symmetry

Added a **Symmetr.** button that turns the central symmetry mode on or off. In this mode, drawing or erasing a cell performs the same action on the opposite side across the center of the board. Both cells are assigned the same color.

## Technical solution

- The main program code is in a single Python file and uses Pygame for the game window and Tkinter for dialogs.
- The playfield is 48 columns × 32 rows; neighbor counts continue across the board edges.
- The generation calculation keeps the existing Game of Life rules and additionally carries or blends cell colors.
- Saved color data is validated when loading the JSON file.

## Validation

The following checks were performed:

- Python syntax check — no errors.
- Pylance diagnostics — no errors.
- Existing automated tests: `python -m unittest test_23_10_py.py` — all 9 tests passed.
- Focused checks were run for color blending, saving and loading colored drawings, reading older save formats, symmetry coordinates, and button rendering.

**Note on test coverage:** the existing 9 automated tests validate the interval-merging program, not the Game of Life functionality. The new Game of Life features were checked with the focused validation listed above; a full manual UI pass was not performed.

## Final result

The program supports creating patterns with the mouse, using multiple colors in one pattern, blending colors of newly created cells, saving and loading drawings, resetting patterns, and drawing with central symmetry.
